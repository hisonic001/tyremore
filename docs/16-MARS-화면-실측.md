# MARS 화면 실측 (2026-08-02)

사장님이 실제로 조작하시는 것을 그대로 기록해서 얻은 값이다 (`npm run mars:watch`).
추측으로 더듬던 것과 여러 군데가 달랐다. **네 번 실패하던 것을 한 번에 다 알아냈다.**

> 모든 화면은 `iframe[title="Main Content"]` 안에 있다.
> 화면 글자보다 **`controlname` 속성**이 훨씬 튼튼하다. 글자로 찾다가 계속 헛짚었다.

---

## 로그인

자동 로그인이 걸려 있어 아이디·비밀번호가 필요 없다.
다만 그 자동 로그인은 **Chrome 프로필**에 있으므로 전용 프로필을 계속 써야 한다
(`tyremore-data/chrome-mars`). 새 프로필로도 한 번에 들어갔다.

- 시작 팝업: `button[controlname="Login Information"]` 의 「확인」
- ⚠️ 지난 실행의 창이 안 닫혀 있으면 프로필이 잠겨 브라우저가 안 뜬다.
  시작할 때 이 프로필을 쓰는 창만 골라 닫는다 (사장님 평소 Chrome 은 안 건드린다).

## 시작 화면

`고객 정보 검색` 은 **button 으로도 menuitem 으로도** 있다. 어느 쪽이든 눌리면 된다.
화면이 다 그려지기 전에 누르면 30초를 기다리다 죽는다 — 이 버튼이 **보일 때까지** 기다린다.

## 🔴 「50개 이상의 레코드」 창

고객 정보 검색을 열면 연락처 2,600건을 불러오려다 이 창이 뜬다.

```
50개 이상의 레코드가 발견되었습니다. 프로세스는 시간이 걸립니다. 진행 하시겠습니까?
                                                        [ 예 ]  [ 아니요 ]
```

**떠 있으면 뒤 화면을 아무것도 못 누른다.** 읽기만 하는 조회라 「예」로 넘긴다.

## 고객 찾기

| | |
|---|---|
| 검색 칸 | `controlname=NameLicensePlate` (「이름/번호판 번호」) |
| 없을 때 | `(이 보기에 표시할 내용이 없음)` |
| 있을 때 | **고객 화면으로 저절로 넘어간다** |

⚠️ 「판매 내역」이 보이는 것을 「찾았다」는 근거로 쓰면 안 된다 —
그건 **검색 결과 화면의 툴바 버튼이라 늘 있다.** 검색 칸이 사라졌는지로 판단한다.

## 고객·차량 생성 (`KOR Cust Contact Veh. Creation`)

동의 표는 **목적(행) × 채널(열)** 이다.

| 목적 | 코드 |
|---|---|
| 비즈니스 목적의 동의 | BUSINESS |
| 마케팅 및 광고 목적의 동의 | MARKETING |
| 제3자 제공 및 국외 이전에 대한 동의 | PERSONAL |

| 칸 | controlname |
|---|---|
| 고객 서명 | `Customer Signed` — `["", "수락된 동의", "거부된 동의"]` |
| 카카오톡·문자 | `Accepts SMS` |
| 전화 통화 | `Accepts Phone Call` |
| 하드카피 | `Accepts Hard Copy` |

- 🔴 **줄을 먼저 눌러 활성화한 뒤**에 그 줄의 칸을 눌러야 먹는다. 이걸 빼먹어 계속 실패했다.
- 🔴 **「고객 서명」을 비워 두면 저장이 막힌다**
  — 「고객이 서명하지 않은 동의 데이터가 아직 있습니다」
- 사장님은 3개 목적 모두 **수락된 동의** + SMS·전화·하드카피를 켜신다.

차량:

| 칸 | 값 |
|---|---|
| 번호판 번호 | 텍스트 |
| 차량 종류 | **`Fuel` · `Hybird` · `BEV` · `Diesel`** ← 그게 전부다 |
| 주행거리 | `controlname=VehicleMileage` |

> ⚠️ `Hybird` 는 MARS 쪽 오타지만 고쳐 넣으면 선택이 안 된다. **LPG 는 없다.**

저장은 **「확인」을 두 번** 눌러야 한다.
① `button[controlname="KOR Cust Contact Veh. Creation"]` ② `button[controlname="Dialog"]`

## 매출 주문

```
판매 내역 → 신규 → 신규 매출 주문
```

🔴 **고객·차량을 다시 고르는 창이 먼저 뜬다.** (내 코드에 아예 없던 단계)
`controlname=NameLicensePlate` 에 번호판 → 결과에서 **「차량」 줄** 선택
→ `button[controlname="Contact Search Results"]`

| 칸 | controlname |
|---|---|
| 현재 주행거리 | `Mileage` |
| 결제 수단 코드 | `<Payment Method Code_2>` — 예 `CREDITCARD` |
| 결제 조건 코드 | `<Payment Terms Code_2>` — 예 `CREDITCARD` |
| 문서 날짜 | `Document Date` |

품목 표 (`div[controlname='Sales Order Subform']` 의 `tr.real-current`):

| 칸 | controlname | 비고 |
|---|---|---|
| 유형 | `Type` | `["", "G/L 계정", "상품", "자원", "고정 자산", "요금(품목)"]` |
| 번호 | `No.` | 품번을 그대로 치면 된다 |
| 수량 | `Quantity` | |
| 단가 부가세 포함 | `Unit Price` | ⭐ **우리 판매가와 기준이 같다** |

> 🔴 **「서비스」라는 유형은 없다.** 타이어·부품 = **상품(2)**, 공임 = **자원(3)**.
> 값은 숫자로 넣는다 (Business Central 표준값이라 화면 글자가 바뀌어도 안 깨진다).

> ⭐ 사장님은 번호 칸에 규격·모델명으로 검색하신다 (`225/55R17` → `h745`, 약 2분).
> 우리는 품번(`HK1026189`)을 이미 갖고 있으니 그 단계를 통째로 건너뛴다.

## 전기 (Posting)

```
menuitem "전기"     controlname=Sales Order
menuitem "전기..."  controlname=Sales Order
button   "확인"     controlname=String Menu     ← 전기 옵션 창, 기본값 그대로
```

결과: **완료된 매출 송장** — 예 `61168583-23SI+003137`

> 🔴 **자동화하지 않는다.** 사장님이 마지막에 검토하고 누르신다 (2026-08-02 지시).
>
> 한때 자동화했다가 되돌렸다. 조작 순서는 위에 적어 두었고
> `tyremore-data/mars-따라하기.log` 에도 남아 있으니 필요하면 되살릴 수 있다.

대신 프로그램은 **대조해서 보여만 준다** — 사장님이 금액을 일일이 따지지 않아도 되게.

```
· 합계 대조 ✅ 500,000원 (공급가 454,545)
```

안 맞으면 이렇게 알린다.

```
· 합계 대조 ⚠️ 우리 500,000원(공급가 454,545)
  MARS 화면에서 찾은 값: 375,000, 340,909
  전기하시기 전에 금액을 꼭 확인해 주세요
```

그리고 **줄이 하나라도 빠지면 「입력 완료」로 넘기지 않는다.**
모자란 채로 대기열에서 내려가면 빠진 줄을 아무도 모르게 된다.
