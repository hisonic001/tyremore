# 06. 가격 계산 설계 (견적 엔진)

확정: 2026-07-31 | 근거: D-05 개정 + 사장님 할인율 구조 설명

---

## 1. 핵심 결정 — 할인율은 "미리 채우지 않는다"

10,691개 품목의 할인율을 사전에 입력하는 것은 불가능하고, 할 필요도 없다.
실제로 파는 품목은 그 중 일부다.

> **할인율은 처음엔 비워두고, 상담하면서 채워진다.**
> 한 번 입력한 할인율은 다음부터 자동 적용된다.

이 방식의 이점:
- **1주차 착수를 막는 블로커가 사라진다** — 할인율 없이도 오픈 가능
- 실제로 파는 품목부터 채워지므로 **몇 주 만에 실전 데이터가 완성**된다
- 안 파는 8천 개 품목에 헛수고를 하지 않는다

---

## 2. 매입과 판매는 별개 축이다

사장님 확인: **매입 할인율과 판매 할인율이 다르다.**
따라서 두 개를 하나로 합치면 안 된다. 각각 별도 필드로 관리한다.

```
                    기표가 (list_price)  ← MARS에서 확보 완료 ✅
                          │
        ┌─────────────────┴─────────────────┐
        │                                   │
   [매입 라인]                          [판매 라인]
   매입 할인율                          판매 할인율
        ↓                                   ↓
   매입 원가                            가이드 판매가
   = 기표가 × (1 − 매입할인율)          = 기표가 × (1 − 판매할인율)
                                            ↓
                                       고객 등급 추가 할인
                                            ↓
                                       시스템 제안가
                                            ↓
                                       현장 재량 조정  ← 항상 허용
                                            ↓
                                       최종 판매가
        │                                   │
        └─────────────┬─────────────────────┘
                      ↓
              마진 = 최종판매가 − 매입원가
```

> 🎁 **부수 효과**: 매입 할인율이 들어오는 순간 **마진이 자동 계산된다.**
> 상담 화면에서 "이 가격에 팔면 얼마 남는가"를 실시간으로 볼 수 있다.
> 현장에서 가격을 깎을 때 **감이 아니라 숫자를 보고 결정**하게 된다.

**실제 매입가를 아는 경우**(입고 명세서 등)에는 계산값 대신 **실매입가를 우선**한다.

## 3. 할인율 적용 우선순위 — 좁은 것이 이긴다

같은 브랜드라도 모델별로 다르다는 점을 반영한다.

| 순위 | 적용 범위 | 예시 |
|---|---|---|
| 1 | **개별 상품(MARS 품번)** | `000425` PILOT SPORT 4 S 245/40R19 → 25% |
| 2 | **패턴/모델** | `PILOT SPORT 4 S` 전체 → 24% |
| 3 | **브랜드** | `MI`(미쉐린) 전체 → 22% |
| 4 | **품목 범주** | `10-TIRES` 전체 → 20% |
| 5 | 없음 | **공란** → 할인 미적용 상태로 표시 |

**좁은 규칙이 넓은 규칙을 덮는다.** 브랜드 기본값을 깔아두고 예외 모델만 따로 지정하면
관리 부담이 최소가 된다.

고객 등급별 추가 할인은 **위 결과에 추가로** 적용한다 (일반 / 단골 / 법인).

## 4. 할인율이 비어 있을 때의 화면 동작 ⭐

이게 이 설계의 핵심이다. **공란이어도 상담이 멈추면 안 된다.**

```
┌─────────────────────────────────────────────────┐
│ Michelin PILOT SPORT 4 S  245/40R19  98Y        │
│                                                 │
│ 기표가            728,000원                      │
│ 판매 할인율       [    ] %      ⚠ 미설정         │
│ 판매가            [        ] 원                  │
│                                                 │
│ ※ 둘 중 아무거나 입력하면 나머지가 자동 계산됩니다  │
└─────────────────────────────────────────────────┘
```

**동작 규칙**
1. **할인율을 넣으면** → 판매가 자동 계산 (728,000 × 0.75 = 546,000)
2. **판매가를 넣으면** → 할인율 자동 역산 (546,000 ÷ 728,000 = 25% 할인)
3. 어느 쪽으로 넣어도 된다. 현장에서 편한 쪽으로.

> 정비사는 "25% 빼주세요"라고 생각하기도 하고 "54만원"이라고 생각하기도 한다.
> **양방향 계산**이 아니면 결국 암산을 하게 된다.

**입력값 저장 제안 (마스터가 채워지는 지점)**
```
┌─────────────────────────────────────────────────┐
│ 이 할인율(25%)을 기본값으로 저장할까요?            │
│                                                 │
│  ○ 이 상품만       (PS4S 245/40R19)             │
│  ○ 이 모델 전체    (PILOT SPORT 4 S)            │
│  ○ 미쉐린 전체                                   │
│  ○ 저장 안 함 (이번만)                           │
└─────────────────────────────────────────────────┘
```

이렇게 하면 **파는 만큼 마스터가 저절로 완성된다.**
사전 입력 작업이 0이면서, 두세 주면 실전에서 쓰는 품목은 다 채워진다.

## 5. 권한 분리 — 마진은 아무나 보면 안 된다

| 정보 | 사장님 | 정비사 |
|---|---|---|
| 기표가 | ✅ | ✅ |
| 판매 할인율 / 판매가 | ✅ | ✅ |
| **매입 할인율 / 매입 원가** | ✅ | ❌ |
| **마진 금액·마진율** | ✅ | ❌ |
| 할인율 기본값 저장 | ✅ | 제한적 (범위 저장은 사장님만) |

> 정비사 화면에는 판매 정보만 보인다. 매입가와 마진은 사장님 계정에서만 노출한다.
> **고객이 화면을 볼 수도 있다**는 점도 고려한 결정이다.

## 6. 데이터 모델 반영

### `price_rule` — 할인율 규칙
| 필드 | 설명 |
|---|---|
| `scope` | `item` / `pattern` / `brand` / `category` |
| `target` | 적용 대상 값 (`000425`, `PILOT SPORT 4 S`, `MI`, `10-TIRES`) |
| `purchase_discount_rate` | **매입** 할인율 (nullable) |
| `sales_discount_rate` | **판매** 할인율 (nullable) |
| `priority` | 1(item) → 4(category). 낮은 값이 이김 |
| `updated_by` / `updated_at` | 누가 언제 정했는지 |

> 매입·판매를 **한 행에 두 컬럼**으로 둔다. 범위가 같으면 대개 함께 관리하기 때문이다.
> 둘 중 하나만 알아도 저장 가능해야 하므로 **각각 nullable**.

### `quote_item` — 견적 항목 (계산 과정 전부 보존)
| 필드 | 설명 |
|---|---|
| `list_price` | 기표가 (스냅샷) |
| `purchase_discount_rate` / `purchase_cost` | 매입 라인 |
| `sales_discount_rate` | 적용된 판매 할인율 |
| `applied_rule_scope` | 어느 범위 규칙이 적용됐는지 (`item`/`brand`/`수동입력`) |
| `customer_discount_rate` | 고객 등급 추가 할인 |
| `suggested_price` | 시스템 제안가 |
| **`final_price`** | **실제 판매가 (현장 조정 결과)** |
| `margin` | `final_price − purchase_cost` (계산 저장) |
| `adjusted_by` | 조정한 사람 |

> `suggested_price` vs `final_price` 차이가 쌓이면
> **"가이드라인이 현실과 맞는가"** 를 데이터로 답할 수 있다.
> 특정 직원이 습관적으로 많이 깎는지도 드러난다.

## 8. 최종 견적 = 타이어 + 부대비용 *(2026-07-31 추가)*

타이어 값만으로는 견적이 안 나온다. MARS 서비스 69건을 확보했으므로 **자동 합산**한다.

```
타이어 최종가 × 본수
  + 휠타이어 교환      × 본수     ← 규격 인치로 자동 선택 (17↓/18↑/21↑)
  + 휠밸런스           × ⌈본수÷2⌉ ← ⚠️ "2개당" 요금 (17↓/20↓/21↑)
  + (선택) 얼라인먼트             ← ⚠️ 국산/수입 · 승용/SUV로 단가 다름
  + (선택) 폐타이어 처리비         ← 미확인
  ─────────────────────────
  = 최종 견적
```

**반드시 자동화할 것 (사람이 고르면 틀린다):**
1. **인치 구간 자동 판정** — 교환은 17/18/21, 밸런스는 17/20/21로 **기준이 다르다**
2. **휠밸런스 수량 = ⌈본수 ÷ 2⌉** — 4본이면 2회. 이걸 놓치면 **매번 절반만 청구**된다
3. **국산/수입 자동 판정** — 차량 제조사(99.7% 보유)로 결정. 얼라인먼트 60,000 vs 80,000

> 부대비용은 **기본 체크된 상태**로 띄우고 빼는 방식으로 한다.
> 넣는 방식이면 바쁠 때 빠뜨리고, 그건 그대로 매출 누락이다.
