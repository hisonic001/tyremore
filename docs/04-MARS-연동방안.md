# 04. MARS 연동 방안

개정: 2026-07-31 (2차) — **본사 협의 불가 확정에 따라 연동 전략 재편**

> **이 문서가 프로젝트의 성패를 가른다.**
> MARS 연동을 못 풀면, 자동화를 해놓고 입력처가 하나 더 늘어나는 결과가 된다.

### 이게 왜 중요한가

**① MARS는 미쉐린이 만든 독자 시스템이 아니다.**
**incadea**(자동차 딜러 관리 시스템 전문 ISV, 현재 Cox Automotive 소속)가 만든
**fastfit** — 타이어·경정비 매장용 상용 패키지다. Business Central 위에 얹힌 표준 제품이다.

> 즉 **문서화된 구조와 표준 연동 수단을 갖춘 시스템**이다. 블랙박스가 아니다.

**② 운영 주체는 타이어모어 코리아 본사다.**
도메인이 `tyremore.co.kr`이다. 다만 **본사와 연동 협의를 진행하는 것은 불가능하다**
(사장님 확인, 2026-07-31). 따라서 "본사에 요청해서 여는" 모든 경로는 검토 대상에서 제외한다.

**③ Business Central은 OData/SOAP 웹 서비스를 표준 탑재한다 — 그러나 우리는 못 쓴다.**
BC의 모든 페이지는 웹 서비스로 발행할 수 있다. **발행 권한은 본사에만 있고, 협의가 불가하다.**
기능의 존재 여부와 무관하게 **우리에게는 닫힌 문**이다. 이 사실을 전제로 설계한다.

## 2. 「웹 서비스 설정」 확인 결과 — 기대와 달랐다

**확인 완료. BC 표준 웹 서비스 페이지가 아니었다.**
fastfit 고유의 **"MARS가 외부 API를 호출하기 위한 설정"** 화면이다.
즉 **MARS를 밖으로 여는 설정이 아니라, MARS가 밖을 부르는 설정**이다. 방향이 반대다.

→ **우리 계정으로 OData를 self-service로 열 수 있는 경로는 없다.**
   본사 협의도 불가하므로 **시나리오 A′는 폐기한다.** (5장 참조)

### ⚠️ API 키 스크린샷 — 왜 신경 쓰는가 *(2026-08-01 재평가)*

이 화면에는 **본사가 계약한 외부 서비스의 API 키가 평문으로 표시된다.**
확인 과정에서 찍은 `mars screenshots/스크린샷 2026-07-31 124647.png`에 실제 키 값이 담겨 있다.

**먼저 — 지금 당장 위험한 상태는 아니다.** 파일은 사장님 PC 폴더 안에 있고,
누가 훔쳐본 정황도 없다. 이건 **사고 대응이 아니라 사고 예방**이다.

**그런데 왜 굳이 정리하는가 — 이유는 셋이다:**

| # | 이유 | 실제로 벌어지는 일 |
|---|---|---|
| 1 | **우리 키가 아니다** | 본사가 네이버·PartZone과 맺은 계약이다. **쓰면 요금이 본사에 청구**되고, 그 청구는 속초점 매니저 계정으로 추적된다 |
| 2 | **하필 지금 본사와 말이 안 통한다** | 본사 협의가 불가한 상태다(D-08). 이런 시점에 키 관련 문제가 생기면 **해명할 창구가 없다** |
| 3 | **파일은 결국 돌아다닌다** | 개발 중 화면 캡처를 주고받게 된다. 이 한 장이 섞여 나가는 게 흔한 사고 경로다 |

**그래서 할 일 — 30초짜리다:**
- ✅ **이 스크린샷은 삭제해도 된다.** 필요한 정보(「웹 서비스 설정」이 BC 웹서비스가 아니라
  MARS가 외부를 호출하는 화면이라는 것)는 **이미 다 뽑아서 이 문서에 기록**했다.
  원본을 계속 들고 있을 이유가 없다.
- 남기고 싶으시면 **키 부분만 칠해서** 저장 (그림판으로 사각형 하나면 된다)
- 이 파일만 **폴더 밖으로 안 내보내면 된다** — 메신저·이메일·공개 저장소 포함

**그리고 이건 절대 규칙이다 (기한 없음, 상시 적용):**
- ❌ **이 키를 우리 시스템에서 사용하지 않는다.** 무단 사용은 명백한 계약 위반이다
- ❌ 프로젝트 문서·코드에 키 값을 기록하지 않는다 *(이 문서에도 기록하지 않았다)*

> 참고: 같은 "폴더 밖으로 내보내지 않는다" 규칙이 **연락처·차량 파일**에도 걸려 있다.
> 그쪽은 실명·휴대폰 2,593건이라 오히려 더 무겁다. 규칙 하나로 둘 다 덮인다.

### 참고 — MARS가 쓰는 외부 서비스 (우리는 사용하지 않음)

이 화면에서 MARS가 연동 중인 외부 서비스 두 곳(PartZone, Naver CLOVA OCR)이 확인됐다.
**둘 다 본사 계약 자산이며, 우리 시스템에서는 사용하지 않는다.**

- 키를 빌려 쓰는 것은 계약 위반이다 (위 보안 경고 3번)
- 우리가 별도 계약하는 방안도 **검토했으나 채택하지 않았다** → D-04 2차 개정
  차량 정보는 **자사 DB 축적으로 해결**한다. 신규 차량만 최초 1회 수기 입력.

> 이 항목은 기록 목적으로만 남긴다. **액션 없음.**

## 4. 파악된 MARS 업무 프로세스

사장님이 알려주신 실제 입력 순서:

```
① 메인화면 → 「고객 정보 검색」
② 고객 유무 확인 → 없으면 고객 + 차량 등록
③ 「신규 매출 주문」 생성
④ 정비내역(상품·서비스) 입력 → 전기(Posting)
⑤ 전기 후 차량점검 보고서 작성
```

### 대응되는 Business Central 개체 (추정)

| 단계 | BC 개체 | 새 시스템 매핑 |
|---|---|---|
| ② | **Contact (`C583-…`)** / Vehicle (`V583-…`) | `customer` / `vehicle` |
| ③④ | Sales Order → Posted Sales Invoice | `quote` → `work_order` |
| ⑤ | Vehicle Inspection Report | 3개월차 정비이력 |

> ⭐ **②에서 만드는 것은 「고객(Customer)」이 아니라 「연락처(Contact)」다.**
> 회계 고객 계정은 `D583/000000`(개인) / `D583/000010`(법인) 두 개가 이미 있고
> 새로 만들지 않는다. **입력 대기열 안내 문구를 여기에 맞춰야 한다.** (D-10 / `docs/07`)

> **④의 "전기(Posting)"는 되돌릴 수 없는 회계 확정 처리다.**
> 어떤 자동화를 하든 이 단계는 **사람이 최종 확인하고 누르는 구조**로 남겨야 한다.

## 5. 연동 시나리오 (2차 개정 — 선택지가 줄었다)

### ❌ 폐기 ①: Excel에서 편집 (시나리오 B)
**「내보내기」만 있고 「Excel에서 편집」은 없음.** 양방향 엑셀 경로 불가.

### ❌ 폐기 ②: OData 웹 서비스 (시나리오 A′) — *2026-07-31 폐기*
Business Central은 구조적으로 OData/SOAP 엔드포인트를 갖는다. 기술적으로는 정답이었다.
그러나 **발행 권한은 본사에만 있고, 본사와의 협의가 불가능하다.**

> 기능이 있어도 **열 수 있는 사람에게 말을 걸 수 없으면 없는 것과 같다.**
> 더 이상 이 경로에 시간을 쓰지 않는다. 미결 사항에서도 삭제한다.

---

### ✅ 시나리오 C — MARS 입력 대기열 (**본안**)
> **실현 가능성 100%.** 승인 불필요. 4주차 구현. **이것이 우리의 MARS 대책이다.**

A′가 사라진 이상 C는 "보장안"이 아니라 **본안**이다. 그만큼 완성도를 높여야 한다.

새 시스템이 **「MARS 미입력 건 목록」** 화면을 제공한다.
- MARS에 안 넣은 건이 목록으로 뜸 → **누락이 구조적으로 불가능해진다**
- MARS 입력 순서(위 4장 ①~⑤)와 **동일한 순서로 필드를 배열**, 항목별 복사 버튼
- 입력 완료 체크 → 목록에서 제거

**A′ 폐기로 인해 C에 추가로 넣을 것 (중요):**
| 보강 | 이유 |
|---|---|
| **원클릭 전체 복사** — 한 건의 모든 필드를 MARS 입력 순서대로 한 번에 | 필드마다 왔다 갔다 하면 결국 수기 입력과 다를 게 없다 |
| **화면 분할 전제 설계** — 왼쪽 우리 시스템 / 오른쪽 MARS 를 상정한 레이아웃 | 사장님이 실제로 이렇게 쓰게 된다 |
| **일괄 처리 모드** — 하루치를 몰아서 넣을 때 다음 건으로 자동 이동 | 매 건 즉시 입력은 현실적으로 안 지켜진다 |
| **미입력 경과일 경고** — 3일 이상 밀리면 상단에 표시 | 누락 방지가 이 기능의 존재 이유다 |

> 목표를 다시 정의한다: **MARS 입력을 없애는 것이 아니라, 옮겨 적는 수고를 0에 가깝게 만드는 것.**
> 사람이 붙여넣고 사람이 누른다. 대신 **보고 옮기고 빠뜨리는 일**이 사라진다.

### ⚠️ 시나리오 D — 화면 자동화 (Playwright) · 선택적 보조
> 사장님이 제안하신 방안. **C가 자리 잡은 뒤에 검토한다. 오픈 범위 아님.**

A′가 사라졌다고 해서 D의 위험이 줄어들지는 않는다. 오히려 **되돌릴 수단이 더 없어졌다.**

**기술적 문제:**
- BC 웹 클라이언트는 가상 스크롤·동적 렌더링이 심한 SPA다. 셀렉터가 불안정하다
- **본사가 fastfit을 업데이트하면 그날로 깨진다** (현재 10.10.00 → 버전업 시 재작업)
- 실패 시 **잘못된 금액이 전기되어 회계 데이터가 오염**될 수 있다. 되돌리기 어렵다

**계약적 문제 — 이제 확인할 방법이 없다:**
- 본사 시스템이므로 자동화 도구 사용이 계약·약관에 저촉될 소지가 있다
- 기존 계획은 "본사에 확인 후 진행"이었으나 **협의가 불가하므로 확인 경로가 없다.**
  → **판단은 사장님 몫**이 된다. 위험을 알고 감수하는 결정이어야 한다.
- 프랜차이즈 계약서·소프트웨어 이용 약관에 관련 조항이 있는지 **문서로 한 번 확인**할 것

**만약 진행한다면 지켜야 할 선 (변경 없음):**
1. **읽기·조회 자동화부터.** 쓰기는 그다음
2. **전기(Posting)는 절대 자동화하지 않는다.** 사람이 화면 보고 누른다
3. 별도 테스트 계정·테스트 회사에서 먼저 검증
4. 실패 시 즉시 중단하고 사람에게 넘기는 안전장치 필수

> **권고**: 먼저 C를 4주차에 완성하고 **한 달간 실제로 써 본 뒤** D를 판단하시라.
> C만으로 충분히 편해질 가능성이 높고, 그렇다면 D의 위험을 질 이유가 없다.

### 결론: **C를 본안으로 완성 → 한 달 운영 → 필요하면 D 검토 (사장님 판단)**

### 코드 체계 정렬
- ⭐ **고객 코드 = 「연락처」 `C583-…`** (`mars_contact_no`). 회계 계정 `D583-…`이 **아니다**

- **서비스센터 코드**: `61168583` (속초점) — 다지점 확장 대비해 필드로 보유
