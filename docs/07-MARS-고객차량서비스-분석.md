## 2. ⭐ 가장 중요한 발견 — 「고객」은 고객이 아니다

「고객」 내보내기에 들어 있는 건 딱 두 줄이다.

| 번호 | 이름 | 고객 그룹 | 매출(LCY) |
|---|---|---|---|
| `D583/000000` | **일반 고객(개인)** | CASH | 839,896,906 |
| `D583/000010` | **외상 고객(거래처/법인)** | FLEET | 0 |

즉 MARS는 **개인 고객을 한 사람씩 회계 고객으로 만들지 않는다.**
개인 매출을 전부 「일반 고객(개인)」 **한 계정에 몰아서** 기표하고,
실제 사람은 **「연락처(Contact)」로 따로 관리**한다.

```
[회계 축]  고객 D583/000000 "일반 고객(개인)"  ← 매출 8.4억이 여기 다 잡힘
                     │
[실무 축]  연락처 C583-xxxxxx "홍길동"  ── 차량 V583-xxxxxx "12가3456"
```

### 우리 시스템에 주는 의미

1. **고객 식별자는 `연락처 번호(C583-…)`다.** `고객번호(D583-…)`가 아니다.
   → `customer.mars_customer_no`는 **`mars_contact_no`로 바꾼다.**
2. **MARS 입력 대기열에는 「고객 계정」이 아니라 「연락처」를 만들라고 안내해야 한다.**
   여기를 잘못 설계하면 4주차 대기열이 통째로 헛돈다.
3. 회계 계정(D583/000000 vs D583/000010)은 **결제 성격 구분**이다.
   → 우리 시스템의 `customer.type` = `개인` / `법인·외상` 두 값이면 충분하다.
4. **법인 외상 계정의 매출이 0이다.** 외상 거래를 MARS에 따로 안 잡고 있다는 뜻일 수 있다.
   → 사장님 확인 필요 (미결로 이관)

> 이 구조를 모르고 설계했다면 "고객이 2명뿐인 시스템"을 만들 뻔했다.
> **내보내기를 미리 받아본 것이 정확히 이 지점에서 값을 했다.**

## 3. 연락처 (= 고객) 2,603건

| 항목 | 결과 |
|---|---|
| 유형 | 사람 2,592 / 회사 11 |
| 비활성 | **0건** (전부 활성) |
| 이름 보유 | 2,597 (99.8%) |
| **휴대폰 보유** | **2,593 (99.6%)** ⭐ |
| 이메일 | **0건** |
| 주소·도시 | 거의 없음 (2건) |

> 🎁 **휴대폰 번호 99.6%.** 문자 알림·재방문 유도의 기반이 이미 갖춰져 있다.
> 2개월차 보관 만료 알림, 환절기 재방문 문자를 **명단 확보 작업 없이** 바로 돌릴 수 있다.
> (발신번호 사전등록만 하면 됨 — 미결 사항)

> ❌ 이메일은 0건이다. **이메일 기반 기능은 설계에서 제외한다.**

### 유형=회사 11건의 정체

`C001-…` 5건은 고객이 아니라 **거래처**다: MICHELIN KR, 지경루브, (주)영일오엔씨,
카매니아, **파트존**.

> 파트존이 연락처에 있는 것은 D-08에서 확인한 **MARS의 PartZone 연동**과 일치한다.
> 우리는 사용하지 않는다 (D-04 2차 개정). 기록용으로만 남긴다.

`C583-000000` 등 6건은 **이름이 비어 있는 껍데기 레코드**다 → 이관 시 제외.

## 4. 차량 2,574건 — 품질이 좋다

| 항목 | 보유 | 비율 |
|---|---|---|
| 번호판 | 2,569 | 99.8% |
| 차량 제조사 | 2,566 | 99.7% |
| 차량 모델 | 2,474 | 96.1% |
| 등록 날짜(연식) | 2,568 | 99.8% |
| 주행거리 | 2,564 | 99.6% |
| **연락처 연결** | **2,569** | **100% 매칭 성공** ⭐ |

- 연락처↔차량 매칭 **실패 0건**. 이름 불일치 **0건**. 관계가 깨끗하다.
- 대부분 1인 1차량 (2,567명). 2대 보유 1명.
- 차량 없는 연락처 35건.
- 등록 날짜는 **차량 연식**이다 (1974~2026 분포, 2020년 피크). 방문일이 아니다.
- 주행거리 중앙값 93,850km.

### 🎯 D-04(자사 DB만) 결정이 옳았음이 확인됐다

**제조사·모델·연식이 이미 99% 채워져 있다.**
차량번호를 치면 `현대자동차 / 그랜저 / 2008년식 / 182,300km`가 **오픈 즉시** 뜬다.
외부 유료 API로 얻으려던 정보의 대부분을 **이미 보유하고 있었다.**

> 다만 **순정 타이어 규격(`oem_tire_size`)은 없다.** 이건 어차피 API를 써도
> 정확도가 들쭉날쭉한 항목이다. → `last_fitted_size`(최근 장착 규격)로 대체한다는
> D-04 2차 개정의 판단이 그대로 유효하다.

### 정제가 필요한 부분

**① 제조사 표기가 48종으로 흩어져 있다** — 같은 회사가 여러 이름으로 들어감

| 실제 | 표기들 |
|---|---|
| 현대 | `현대자동차` 956 / `현대` 53 / `HYUNDAI` 17 |
| 기아 | `기아자동차` 714 / `기아` 29 / `KIA` 8 |
| 르노 | `르노 (삼성) 코리아` 112 / `르노삼성` 4 / `RENAULT` 3 / `르노` 1 |
| 쌍용 | `KG모빌리티(쌍용)` 101 / `쌍용` 6 / `KG모빌리티` 1 |
| 벤츠 | `MERCEDES-BENZ` 81 / `벤츠` 3 |
| 폭스바겐 | `VOLKSWAGEN` 9 / `VW` 5 |
| 테슬라 | `TESLA` 18 / `테슬라` 3 |

→ **이관 시 매핑 테이블로 약 25종으로 통합한다.** 반나절 작업.
   통합 안 하면 "현대"로 검색했을 때 절반이 안 나온다.

**② 번호판 이상치 11건 (0.4%)**
`그랜드카니발`(차종이 들어감), `01034890392`(전화번호), `000속초0000`, `강원61사65557`(구형식)
→ 이관 시 목록으로 뽑아 사장님이 직접 보정.

**③ 중복 번호판 4건** — `39저5427`, `169허5867`, `91두6855`, `336도7161`
→ 차량 교체 후 이전 등록이 남았을 가능성. 확인 후 통합.

> ⚠️ 인치 구간이 **교환은 17/18/21**, **밸런스는 17/20/21**로 다르다. 헷갈리기 쉽다.
>    → 규격에서 인치를 읽어 **자동 선택**시킨다. 사람이 고르게 하면 틀린다.

### 경정비 공임 (3개월차 → 조기 확보)

브레이크(패드·디스크·캘리퍼·드럼·라이닝), 엔진오일, 배터리, 점화장치, 연료필터,
하체정비(쇼바·로우암·타이로드·등속조인트), 얼라인먼트, 스캔진단, 에어컨필터, 전구류 등
**국산/수입 구분까지 되어 있다.**

| 예 | 국산 | 수입 |
|---|---|---|
| 휠얼라인먼트 (승용) | 60,000 | 80,000 |
| 브레이크패드 교환(좌우1세트) | 30,000 | 50,000 |
| 엔진오일 교환 | 30,000 | 50,000 |
| 스캔 진단 | 20,000 | 30,000 |

- 점검류 9종은 전부 5,000원
- 기본 「서비스 공임」 = 80,000원 (`S001/0000`)
- 단가 없는 3건: `휠 수리`, `TPM센서`, `기타` → 건별 입력 항목

> **국산/수입 구분이 있다는 것은 차량 제조사를 알아야 공임이 정해진다는 뜻이다.**
> 4장에서 확인했듯 제조사는 99.7% 확보돼 있다. **자동 판정이 가능하다.**
> → 견적 화면이 차량을 보고 국산/수입 공임을 알아서 고르게 만든다.

### 여전히 없는 것

- ❌ **폐타이어 처리비** — 서비스 목록에 없다. 사장님 확인 필요
- ❌ 고객 등급별 할인 — MARS 고객 그룹은 `CASH`/`FLEET` 둘뿐

## 6. 데이터 품질 이슈와 이관 방침

| 이슈 | 규모 | 방침 |
|---|---|---|
| **동일 이름+동일 전화 중복** | 139건 | 이관 시 **자동 병합 후보로 제시**, 사장님이 확인 |
| 동일 전화+다른 이름 | 72그룹 | **가족·법인 관계다. 병합하면 안 된다.** 별도 유지 |
| 이름에 메모가 섞임 | 107건 | `고태환[한진택배]`, `김금미(속초가온누리)` 등 |
| 제조사 표기 분산 | 48종 | 매핑 테이블로 25종 통합 |
| 번호판 이상 | 11건 | 목록 출력 → 수동 보정 |
| 이름이 차량번호 | 3건 | `163머4819` 등 — 수동 보정 |

### 이름 속 메모 107건은 지우지 말 것

`고태환[한진택배]`, `권동식[코리아횟집]`, `129구급대[아들분]` —
**사장님이 손님을 기억하는 방식**이다. 정규화한답시고 날리면 현장에서 사람을 못 찾는다.

> 방침: `name`은 **원문 그대로 보존**하고, 괄호 안을 `memo`에 **복사**해 둔다.
> 검색은 둘 다 뒤진다. 지우는 건 나중에 사장님이 판단할 일이다.

### 중복 판정 규칙 (이관 스크립트)

```
동일 전화 + 동일 이름  → 병합 후보 (기본 병합, 사장님이 해제 가능)
동일 전화 + 다른 이름  → 별개 유지 + "가족 그룹"으로 묶어 표시
동일 이름 + 다른 전화  → 별개 유지 (동명이인)
```

## 7. 1주차 작업에 미치는 영향

**줄어든 것**
- 고객·차량 마스터 수기 구축 → **불필요**
- 경정비 공임 조사(3개월차 예정) → **불필요. 69건 확보**
- 부대비용 조사(3주차 블로커였음) → **해소**
- 보관료 요금 체계 조사(2개월차 블로커였음) → **해소**

**새로 필요한 것**
- 제조사 표기 통합 매핑 (반나절)
- 중복 연락처 병합 확인 화면 (반나절)
- 번호판·이름 이상치 14건 보정 화면 (기존 상품 파싱 보정 화면 재사용)
- **`mars_customer_no` → `mars_contact_no` 모델 수정** (2장)

**순증감: 1주차 공수 추가 감소.** 3주차·2개월차 블로커까지 앞당겨 해소됐다.
