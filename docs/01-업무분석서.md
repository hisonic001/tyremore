## 1. 한 줄 진단

> **MARS·엑셀·수기 장부 세 곳에 데이터가 갈라져 있어,
> 정보가 필요한 순간(고객 앞)에 정보가 없다.**

타이어모어의 문제는 "기록을 안 해서"가 아니다. 오히려 **세 번씩 기록하고 있다.**
문제는 그 기록이 **필요한 순간·필요한 장소에서 조회되지 않는다**는 것이다.

기록량은 이미 과잉이고, 활용도는 0에 가깝다. 이 격차가 문제의 전부다.

## 2. 현재 업무 흐름과 병목

### 2-1. 고객 상담 (병목 ★★★)

```
고객 방문
  → 차량 확인, 규격 파악          [정비사 경험에 의존]
  → 재고 있나?                    ⛔ 창고 가서 눈으로 확인
  → 얼마인가?                     ⛔ 기표가표 뒤적 + 할인율 암산
  → 경정비까지 합치면?            ⛔ 부대비용 별도 암산
  → 고객에게 구두 안내
```

**병목의 정체**: 고객은 서 있고, 답은 창고와 종이 사이에 흩어져 있다.
이 시간이 길어지면 고객은 "알아보고 올게요" 하고 떠난다. **이탈이 곧 매출 손실이다.**

### 2-2. 재고 관리 (병목 ★★★)

```
도매처 입고 → 명세서 확인 → 엑셀에 수기 입력 → 창고 적재
판매 출고   → (엑셀 차감이 밀림) → 실재고와 장부재고 괴리 발생
```

**병목의 정체**: 출고는 현장에서 일어나는데 엑셀은 사무실 PC에 있다.
현장과 장부 사이에 시차가 생기고, 그 시차가 2-1의 "창고 가서 눈으로 확인"을 강제한다.
**즉 재고 부정확이 상담 지연의 근본 원인이다.**

### 2-3. 타이어 보관 서비스 (병목 ★★★ — 관리 체계 부재)

사장님이 꼽은 문제 4가지가 **전부** 해당됨:

| 문제 | 실제로 벌어지는 일 |
|---|---|
| 보관 위치를 못 찾음 | 고객이 왔는데 창고에서 헤맴 |
| 누가 뭘 맡겼는지 목록 없음 | 재고인지 보관품인지 헷갈림 → 남의 타이어를 팔 위험 |
| 만료·보관료 청구 누락 | 방치 타이어 누적, 받아야 할 보관료를 못 받음 |
| 재방문 유도 안 됨 | 환절기 교체 대상 명단을 못 뽑아 전화 못 함 |

**이건 병목이 아니라 공백이다.** 관리 체계 자체가 없다.
동시에 **가장 확실한 재방문 매출원**을 놀리고 있다는 뜻이기도 하다.

### 2-4. 정비이력 (병목 ★★)

수기 전표로 남기니 **입력은 되는데 검색이 안 된다.**
"이 차 언제 오일 갈았지?"에 답하려면 전표철을 넘겨야 한다. 사실상 답을 포기하게 된다.

### 2-5. 정산·매출 (병목 ★★)

일·월 매출 집계, 부가세 자료 정리를 월말에 몰아서 수작업.
제휴 플랫폼 정산 내역과 자사 매출을 눈으로 대조하는 작업이 특히 소모적.

### 2-6. MARS 입력 (병목 ★★★ — 가장 큰 순수 낭비)

미쉐린 프랜차이즈 가맹점이므로 **본사 시스템 MARS에 고객·업무·결제 정보를 입력할 의무**가 있다.
그런데 지금은 **MARS 화면에 건별로 하나씩 수기 입력**하고 있다.

```
작업 1건 완료
  → 수기 전표에 기록          [1회차]
  → 엑셀에 옮겨 적기          [2회차]
  → MARS 화면에 또 입력       [3회차] ⛔
```

**병목의 정체**: 같은 정보를 세 번 타이핑한다.
게다가 세 곳 중 어느 것도 서로를 모른다. **어느 건을 MARS에 안 넣었는지 알 방법이 없다.**
누락이 생겨도 발견되지 않고, 발견하려면 대조 작업을 또 해야 한다.

**이건 순수한 낭비다.** 2-1~2-5는 그래도 뭔가를 얻기 위한 작업이지만,
MARS 재입력은 이미 가진 정보를 옮겨 적는 것 외에 아무 가치를 만들지 않는다.

> ⚠️ **동시에 이 프로젝트 최대의 함정이기도 하다.**
> 새 프로그램을 만들면서 MARS 입력을 그대로 두면, 입력처가 **4개**로 늘어난다.
> 자동화를 하고서 일이 늘어나는 것이다. 새 시스템은 반드시 MARS 입력을 **흡수**해야 한다.
> → 상세: `04-MARS-연동방안.md`

**반전 하나**: MARS에는 **엑셀 내보내기 기능이 있다.**
즉 지금까지 세 번씩 입력해 온 고객·차량·결제 데이터가 **이미 쌓여 있고, 꺼낼 수 있다.**
그동안의 헛수고가 새 시스템의 출발 자산이 된다.

## 3. 근본 원인 3가지

문제 6개는 겉으로 다르게 보이지만, 원인은 3개다.

**① 데이터가 있어야 할 곳에 없다**
사무실 PC의 엑셀 ↔ 현장의 타이어. 정비사는 폰을 들고 있는데 시스템이 폰에 없다.
→ **해법: 폰·태블릿에서 열리는 웹앱**

**①-b 시스템이 서로를 모른다** *(①의 확장)*
MARS·엑셀·수기 장부가 서로 대화하지 않아, 사람이 매번 손으로 옮기고 손으로 대조한다.
→ **해법: 새 시스템을 원본으로 삼고, MARS로는 자동 생성된 데이터를 흘려보낸다**

**② 마스터 데이터가 없다**
상품이 무엇인지, 정가가 얼마인지, 할인율이 어떻게 되는지가 시스템화되어 있지 않다.
그래서 매번 사람이 종이를 찾고 암산한다.
→ **해법: 상품·가격 마스터 구축 (모든 자동화의 토대)**

**③ 개별 식별 수단이 없다**
"이 타이어 한 본"을 가리킬 방법이 없어서, 보관·이력 추적이 원천적으로 불가능하다.
→ **해법: 시스템 자동 채번 + 보관품 스티커**

## 4. 자동화 기회 평가

| 영역 | 효과 | 난이도 | 우선순위 |
|---|---|---|---|
| 상담 중 즉시 견적 | ★★★ 매출 직결 (이탈 방지) | 중 | **1차** |
| 재고 실시간 정확도 | ★★★ 위 기능의 전제조건 | 중 | **1차** |
| MARS 데이터 가져오기 | ★★★ 고객·차량 DB를 공짜로 확보 | 하 | **1차** |
| MARS 입력 자동화 | ★★★ 순수 낭비 제거 | 상 (본사 의존) | 1차(대기열)→2차 |
| 타이어 보관 관리 | ★★★ 공백 영역, 재방문 매출 | 하 | 2차 |

## 5. 이 프로젝트의 최대 리스크

**기술이 아니라 정착이다.**

월 300~800본을 처리하는 현장에서, 시스템 입력이 엑셀보다 조금이라도 느리면
직원들은 3주 안에 예전 방식으로 돌아간다. 그러면 데이터가 반쯤 빈 상태가 되고,
반쯤 빈 데이터는 안 쓰느니만 못하다.

**따라서 설계 원칙은 하나다.**

> 모든 화면은 **"엑셀보다 빠른가?"** 를 통과해야 한다.
> 입고는 스캔 한 번, 견적은 탭 세 번, 보관 조회는 차량번호 한 번.

부수 원칙:
- 현장 재량 오버라이드를 막지 말 것 (가격 조정은 반드시 허용)
- 필수 입력 항목을 최소화할 것 (DOT는 나중에 채워도 되게)
- 정비사는 장갑을 끼고 더러운 화면을 만진다 — 버튼을 크게
