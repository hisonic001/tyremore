## 2. ✅ 타이어 — 완벽하다

### MARS 품번과 100% 일치

재고 파일의 `코드`(6자리)가 **MARS 품번 그대로**다.

```
178959 → MARS 000? 아니라 178959
       → "Michelin 175/65 R 15 88H TL" / CROSSCLIMATE 2 / 기표가 157,000원
```

**57종 전부 매칭.** 즉 재고 엑셀만 넣으면 브랜드·패턴·규격·기표가가 **자동으로 붙는다.**
사람이 손댈 것이 없다.

### ⭐ DOT를 이미 세고 계셨다 — D-02의 전제가 바뀐다

```
DOT(수량) 컬럼:  0526[8]1126[1]1826[3]
                  └ 5주2026년 8본, 11주 1본, 18주 3본
```

- DOT 항목 **107개, 합계 296본** — 사실상 전량에 DOT가 있다
- **품질도 좋다. 이상 3건뿐** (57종 중)

| 이상 | 내용 |
|---|---|
| `015692` | `18826[2]` — 5자리. `1826` 오타로 보임 |
| `126081` | DOT 합 31 ≠ 수량 27 — 4본 차이 |
| `520336` | 수량 0인데 DOT 2본 + `타이어핑판매` 메모 |

> **D-02는 "DOT는 최초 입고 시 필수 아님, 나중에 보완"이었다.**
> 실제로는 **이미 DOT별 수량을 세고 계신다.** 시스템이 이걸 못 받으면 오히려 후퇴다.

### 🎁 DOT가 있으니 재고 노후화 관리가 공짜로 된다

| 연식 | 본수 |
|---|---|
| 2024년산 | 5본 |
| 2025년산 | 89본 |
| 2026년산 | **202본** |

> 타이어는 오래되면 안 팔린다. **"2024년산 5본이 남아 있다"** 를 시스템이 먼저 알려줄 수 있다.
> 원래 계획에 없던 기능인데, 데이터가 이미 있으니 **화면 하나만 추가하면 된다.**

### ⭐ 입고 화면 설계를 바꾼다

엑셀이 이미 **가장 자연스러운 입력 형태**를 보여주고 있다. 그대로 따른다.

```
기존 설계:  스캔 → 수량 [4] → 확정
변경 설계:  스캔 → DOT별로 입력
            ┌──────────────────────────┐
            │ DOT [1826]  수량 [ 14 ]  │
            │ DOT [    ]  수량 [    ]  │  ← 필요하면 줄 추가
            │              합계  14본  │
            └──────────────────────────┘
```

- 한 박스가 전부 같은 DOT면 **한 줄로 끝난다** (실데이터에서 흔하다: `1826[14]`, `1926[14]`)
- DOT를 모르면 **비워도 통과** — 기존 D-02 원칙 유지
- 이 방식이면 **입력 부담 없이** 1본 단위 DOT 추적이 실제로 굴러간다

## 3. ❌ 부품류 — MARS에 없다

### 코드 체계가 다르다

| 파일 | 코드 예 | 정체 |
|---|---|---|
| 에어필터 | `MAA-049`, `MAB-054` | 부품 공급사 자체 품번 |
| 오일필터 | `MBA-001`, `MBB-002` | 〃 |
| 에어컨필터 | `MMA-011`, `MMA-C51` | 〃 |
| 브레이크패드 | `SM160`, `FPH01`, `SP1915` | 상신·프릭사 등 제조사 품번 |

MARS 비타이어 품목 372건은 **ATE·TEXTAR·BOSCH 등 수입 부품** 중심이고,
재고 파일의 **국산 부품 품번과는 완전히 다른 체계**다. 매칭 265종 중 4종뿐.

### 의미: 부품은 **우리 시스템이 원본이 된다**

타이어는 MARS가 마스터를 갖고 있어 "이관"이지만,
**부품은 MARS에 없으므로 우리가 처음부터 만든다.** 그리고 MARS로 보낼 필요도 없다.

> 이건 나쁜 소식이 아니다. **MARS 눈치를 볼 필요가 없는 영역**이 생긴 것이다.

### 부품 검색은 축이 완전히 다르다

타이어는 **규격**(225/45R17)으로 찾지만, 부품은 **적용 차종**으로 찾는다.

```
"MBA-039 | 제네시스 DH / 펠리세이드 | 5개"
"SM188   | 쏘나타 DN8 16", 투싼 NX4 | 앞 | 2개"
```

→ **`적용 차종` 부분검색**이 부품 검색의 전부다.
→ 차량을 이미 조회한 상태라면(화면 2) **그 차에 맞는 부품만 자동으로 걸러줄 수 있다.**

### 없는 정보

| 항목 | 상태 |
|---|---|
| 매입가·판매가 | ❌ **재고 파일에 없음.** 부품 견적을 내려면 필요 |
| 바코드 | ❌ 없음 → 부품은 **스캔이 아니라 검색으로 출고** |
| 브레이크패드 `위치`(앞/뒤) | ✅ 있음 — 중요한 구분자다 |

**값이 있는 것은 전부 음수다.** 판매만 잡히고 입고가 안 잡힌 상태로 보인다.

> 재고에서 특히 분명해진다. 재고는 **우리가 100% 책임진다.**

## 4-B. ⭐ 부품 수량은 쓰지 않는다 *(사장님 확인, 2026-07-31)*

> **"필터류 재고는 사실 맞지 않음. 확실한 것은 미쉐린 타이어 재고 뿐임."**

이 한마디로 부품 재고의 처리 방침이 정해졌다.

### 세 가지 선택지와 판단

| 안 | 문제 |
|---|---|
| ❌ 엑셀 수량을 그대로 넣는다 | **한 번 틀린 숫자를 보면 그다음부터 아무도 안 믿는다** |
| ❌ 전부 0으로 넣는다 | 출고할 때마다 "재고 없음"이 뜬다. 정비사가 시스템을 우회하게 된다 |
| ✅ **`미확인` 상태로 시작한다** | 숫자 대신 `미확인` 표시. 실물 셀 때 그 자리에서 확정 |

**확정: 3안.** 품목 마스터(265종)는 이관하고 **수량만 `미확인`으로 둔다.**

```
┌─────────────────────────────────────────┐
│ MBA-039  제네시스 DH / 펠리세이드        │
│ 재고     미확인          [ 지금 세기 ]   │
└─────────────────────────────────────────┘
       ↓ 실물 5개 확인 후 입력
┌─────────────────────────────────────────┐
│ MBA-039  제네시스 DH / 펠리세이드        │
│ 재고     5개    ✅ 7/31 확인             │
└─────────────────────────────────────────┘
```

> **D-05(할인율)·D-02(DOT)와 같은 철학이다.**
> 미리 다 채우려 하지 않고, **쓰면서 정확해지게** 만든다.
> 부품은 자주 나가는 20~30종부터 자연스럽게 확정될 것이다.

### 부수 효과

1. **오일필터 시트 충돌 문제가 사라진다.** `오일필터` vs `Sheet1` 중 무엇을 고를지
   고민할 필요가 없다 — **어느 쪽도 수량으로 쓰지 않는다.** 품목 목록만 합쳐서 쓴다
2. **재고 실사 화면이 필요해진다** → 2주차에 넣는다.
   부품 확정용으로 만들지만, **4주차 타이어 실사에도 그대로 쓴다.** 어차피 필요했다
3. **성공 지표를 명확히 한다** — "재고 정확도 95%"는 **타이어 기준**이다

## 6. 데이터 모델 수정 사항

`09-데이터모델-확정.md`를 아래와 같이 고친다.

### ① `tire_product` → `product` 로 일반화

부품 265종이 들어오므로 타이어 전용 테이블로는 안 된다.

```sql
ALTER: tire_product → product
  + item_type      text   -- 'tire' | 'part'
  + is_serialized  boolean -- 타이어=true(1본1행), 부품=false(수량관리)
  + part_no        text   -- 'MBA-039','SM188' 공급사 품번
  + fitment        text   -- '제네시스 DH / 펠리세이드' 적용 차종
  + position       text   -- '앞'|'뒤' (브레이크패드)
  + stock_tracked  boolean -- ⭐ false면 '미등록' 표시 (0본과 구분) — 9장
  ; width/aspect_ratio/rim_inch 등 타이어 컬럼은 전부 nullable 유지

CREATE INDEX idx_product_fitment ON product USING gin (fitment gin_trgm_ops);
CREATE INDEX idx_product_partno  ON product(part_no);
```

### ② `stock_item`에 `qty` + `verified_at` 추가

```sql
ALTER TABLE stock_item
  ADD COLUMN qty         integer NOT NULL DEFAULT 1,
  ADD COLUMN verified_at timestamptz,   -- ⭐ NULL이면 화면에 '미확인' 표시
  ADD COLUMN verified_by bigint REFERENCES app_user(id);
```

| 상품 | 동작 |
|---|---|
| 타이어 (`is_serialized=true`) | 1본 = 1행, `qty`는 항상 1, `dot` 보유. **이관 시 `verified_at` 채움** |
| 부품 (`is_serialized=false`) | 1행에 수량. **`verified_at`을 비워 이관** → `미확인` |

> 테이블을 둘로 쪼개지 않는다. **재고 현황·출고 화면을 하나로 유지**하는 게 현장에 낫다.
> `verified_at`은 4주차 타이어 실사에도 그대로 쓴다.

### ③ DOT 입력을 입고 화면 1급 시민으로

`stock_item.dot`은 이미 있다. **화면만 바꾼다** (2장).
`import_issue`에 `kind='dot'` 추가 — 이상 3건 처리용.

## 9. ⭐ 미쉐린 외 브랜드 — 「0본」이 아니라 「미등록」 *(2026-08-01)*

> "다른 타이어도 재고가 있지만 우선 어느정도 프로그램이 돌아가는 것을 확인하고
> 재고 수정 및 추가 기능을 활용해서 입력할 예정."

합리적인 순서다. 다만 **그냥 두면 화면이 거짓말을 한다.**

상품 마스터에는 브랜드 18종 10,691건이 전부 들어온다. 재고 테이블에는 미쉐린만 있다.
→ 규격 검색에서 **`한국 K127 · 재고 0본`**이 뜬다. 창고에는 있는데.

한 번 이런 화면을 보면 정비사는 **재고 숫자를 통째로 안 믿는다.**
D-12 5번(부품 `미확인`)에서 피한 것과 **똑같은 함정**이다.

### 해법 — `product.stock_tracked`

| `stock_tracked` | 재고 | 표시 | 뜻 |
|---|---|---|---|
| `true` | 4 | 🟢 **4본** | 있다 |
| `true` | 0 | 🔴 **0본 · 소진** | 정말 없다 → 주문 |
| `false` | 0 | ⚪ **미등록** | **모른다 → 창고 확인** |

- 1주차 이관 시 미쉐린 57종만 `true`. 나머지는 `false`.
- **최초 입고가 확정되는 순간 `true`로 바뀐다.** 사장님이 넣는 만큼 하나씩 켜진다.
- 화면 3(규격 검색)에서 **미등록은 접지 않는다.** 소진된 것만 접는다.
  접으면 안 보이고, **안 보이면 못 판다.**
- **미등록이어도 견적은 그대로 나온다.** 기표가·할인율은 마스터에 있다.

### 입고 화면 보강

스캐너 앞에 박스를 들고 가야 한다면 브랜드를 넓히는 일이 밀린다.

- **[검색] 탭** — 규격·브랜드·모델로 찾아 바로 입고 (부품과 같은 경로)
- **[일괄] 탭** — 확정해도 화면이 안 닫히고 **커서가 검색창으로 복귀** → 연속 입력
- **DOT는 선택.** 나중에 채우는 재고라 모를 수 있다 → 비워도 통과 (D-02)
- 수량 **정정**은 화면 8c(재고 실사)에서. **넣는 건 입고, 고치는 건 실사.**
